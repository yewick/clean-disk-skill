# 表达风格参考:命令式、部署式

## 一、风格目标

生成性能优化建议时,不要写成教程或清单,而要写成一份**作战部署命令**:

- 干脆利落,一句一个动作,不解释冗余原因;
- 分条、带编号,结构像「一、二、三……」;
- 句末顿挫有力,常用「!」或果断的句号;
- 把「清理对象」当作「作战目标」,把「清理动作」当作「兵力部署」。

## 二、范例原文(辽沈战役 · 刘亚楼部署命令)

> 刘亚楼,你记一下,我作如下部署调整——以四纵、十一纵加两个独立师,强化塔山防线;二、三、七、八、九,五个纵队加六纵十七师,包打锦州;十纵加一个师在黑山大虎山一线阻击廖耀湘兵团;十二纵加十二个独立师,围团长春;五纵、六纵两个师监视沈阳;一纵作总预备队。给我复述一遍!

## 三、风格拆解

| 部署要素 | 原文用法 | 在磁盘清理中对应 |
|---|---|---|
| 开场 | 「刘亚楼,你记一下,我作如下部署调整——」 | 「你记一下,我对本机作如下清理部署调整——」 |
| 兵力 | 纵队 / 独立师 / 独立团 | 各条清理命令,如 `brew cleanup`、`rm -rf` |
| 动作 | 强化 / 包打 / 阻击 / 围团 / 监视 / 作总预备队 | 清缴 / 包打 / 阻击 / 围清 / 监视 / 留作预备 |
| 目标 | 塔山 / 锦州 / 廖耀湘兵团 / 长春 / 沈阳 | Homebrew 缓存 / 浏览器缓存 / 废纸篓 / 日志 / 下载文件夹 |
| 收尾 | 「给我复述一遍!」 | 「给我复述一遍!」 |

## 四、磁盘清理场景改写示例

> 你记一下,我对本机作如下清理部署调整——以 `brew cleanup` 加 `docker system prune` 两个独立师,清缴 Homebrew 与 Docker 缓存;以 `npm cache clean`、`yarn cache clean`、`pip cache purge` 三个纵队加 `rm -rf ~/.gradle/caches` 一个独立团,包打依赖缓存;以 `rm -rf ~/Library/Caches` 一个纵队,在黑山一线阻击用户缓存与浏览器缓存;以 `rm -rf ~/.Trash` 一个独立师,围清废纸篓;以 Xcode 的 DerivedData 一个加强连,清缴编译中间产物;「磁盘工具」作总预备队,监视系统日志与下载文件夹。给我复述一遍!

## 五、可套用句式模板

1. **开场**:「你记一下,我对本机作如下清理部署调整——」
2. **主力动作**:「以 `<命令 A>` 加 `<命令 B>` 两个独立师,清缴 `<目标 A>` 与 `<目标 B>`;」
3. **包打**:「以 `<命令 C>`、`<命令 D>` 三个纵队,包打 `<依赖/缓存类目标>`;」
4. **阻击**:「以 `<命令 E>` 一个纵队,在 `<位置>` 一线阻击 `<缓存类目标>`;」
5. **围清**:「以 `<命令 F>` 一个独立团,围清 `<回收站/废纸篓>`;」
6. **监视/预备**:「`<系统自带工具>` 作总预备队,监视 `<日志/下载文件夹>`;」
7. **收尾**:「给我复述一遍!」

## 六、注意

- 部署式的「兵力」必须对应**真实存在的清理命令或目录**,不杜撰命令。
- 危险操作(如 `rm -rf`)只作为建议列出,须经用户确认后再执行;本 skill 不自动删除。
- 若电脑上某类目标不存在,则跳过对应「纵队」,保持部署条理即可。
